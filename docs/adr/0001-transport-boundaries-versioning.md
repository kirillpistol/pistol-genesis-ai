# ADR-0001: транспорт, границы уровней и версии

Дата: 2026-10-02. Статус: принято для прототипа v1.

## Контекст

Нужен измеримый core без встроенных датасетов, с переносом завершённого состояния
и подключением независимо разрабатываемых алгоритмов и внешних источников.
Предыдущий архив имел неверсионированный HTTP API и in-process реестр алгоритмов.

## Решение

Транспорт первой реализации — HTTP/1.1 с JSON поверх HTTPS и обязательным mTLS
для сетевого режима. API пути /v1/*, api_version="1.0". HTTP без TLS допускается
только с явным --dev-local и адресом 127.0.0.1. gRPC отложен до необходимости
типизированного high-throughput взаимодействия/streaming. WebSocket отложен до
необходимости двунаправленного event stream. Поддержки обоих сейчас нет.

Уровень 1 отвечает за жизненный цикл, контракт, исполнение, snapshots, allowlist,
защищённый транспорт и discovery. Уровень 2 отвечает за значение входов, алгоритм,
агрегаты и оценку. Уровень 3 доставляет данные без импорта кода в ядро.
Discovery — отдельный процесс-компонент уровня 1: проверяет заданные peers,
не устанавливает алгоритмы и не запускает серверы. Snapshot не содержит конфигурации
доверия/ключей: приёмник использует собственную конфигурацию.

Сейчас алгоритмы — явно установленные доверенные локальные классы. Изолированный
worker-протокол будущий; mTLS не делает вредоносный локальный Python безопасным.

Разделяем версии API, state_version snapshot и version каждого алгоритма.
Данная реализация принимает только API 1.0, state_version=1 и точную версию алгоритма.
Неизвестные поля управляющих сообщений и несовместимые версии отклоняются.
Минорные версии автоматически не принимаются. Изменения контракта требуют тестов
совместимости; новый major получает новый каталог схем/пути. Миграций snapshot нет.

Перенос — только между завершёнными process(). Источник блокирует новые задачи,
фиксирует snapshot на конкретный destination_instance и остаётся paused.
Повтор передачи того же snapshot одному приёмнику допустим. Другой экземпляр
не может принять snapshot; перезапуск меняет instance. Диск/распределённые leases
не используются. Администратор с правом запуска может обойти ограничения:
не заявляем распределённый консенсус или exactly-once. Автозапуск/самоперенос пока нет.

Обучение и /exchange из архивного примера намеренно исключены из v1.
Numeric вычисляет агрегаты, evaluator оценивает фиксированные прогнозы на явных targets.
Это не обученный предиктор и не доказательство улучшения ML.

## Замена архивного API

Архивный HTTP официально заменён опубликованным level1_core, а не совместимым shim.
/status → /v1/status; /tasks → /v1/tasks с api_version;
/checkpoint → /v1/snapshot с destination_instance;
/restore → /v1/restore с новой схемой. Старые snapshots не принимаются.
/algorithms/attach → /v1/algorithms/attach; /exchange удалён до следующего этапа.
Старый локальный планировщик и inventory сохранены с прежними командами.

## Последствия

Stdlib Python 3.10+ без Python-зависимостей. Для генерации тестовых сертификатов
нужен openssl. CA, hostname и SHA256 DER-certificate pins проверяются до отправки данных.
Ключи не входят в репозиторий. Pin rotation и выпуск production сертификатов — внешняя процедура.
Синхронный процесс без sandbox не имеет безопасного прерывания зависшего алгоритма.
Прототип не позиционируется как production или безуязвимая система.
