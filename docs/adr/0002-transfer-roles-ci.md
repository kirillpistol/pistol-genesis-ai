# ADR-0002: staged transfer, роли, наблюдаемость и совместимость

Дата: 2026-10-02. Статус: реализовано для RAM-only прототипа; ограничения ниже обязательны.

## Совместимость /v1

Формы существующих успешных v1.0 ответов заморожены, неизвестные управляющие поля
по-прежнему отклоняются. Correlation ID передаётся заголовком, не меняет envelope.
Новые возможности — дополнительные endpoints; старый сервер может вернуть на них 404.
Старые /v1/snapshot и /v1/restore сохраняются для frozen v1 клиентов, но не обеспечивают
resume/rollback. Новые клиенты для этих гарантий используют /v1/transfers/*.
Отдельной поддержки прежнего архивного неверсионированного API нет.

Политика deprecation: удаление существующей v1 операции/поля — только после
публичного объявления, не менее 180 дней и двух совместимых опубликованных выпусков,
в зависимости от того, что наступит позже. Major изменения — /v2, с периодом совместного
обслуживания. Сейчас дата удаления v1 endpoints не назначена. Wire api_version остаётся
"1.0"; новые minor версии не принимаются автоматически и не заменяют поддержку 1.0.

CI во всех трёх репозиториях запускается на push/PR/workflow_dispatch и ежедневно.
Проверяет текущую цепочку и immutable v1 baselines в ci/baselines.json, оба направления
old-client/new-server и new-client/old-server. Процессы не разделяют Python imports.
Изменяемый репозиторий проверяется на github.sha, остальные — checkout main на момент
выполнения. Версии baselines не обновлять без review политики совместимости.
CI проверяет взаимодействие конкретных трёх commit-ов, не всех исторических версий.

## Перенос

prepare(source) фиксирует canonical JSON snapshot и SHA256, destination_instance,
transfer_id и хеш случайного activation token; source paused. Размер до 65536 байт.
begin(destination) резервирует один буфер в RAM и приостанавливает приёмник.
Далее download(source)/chunk(destination) передают до 4096 байт за запрос.
progress показывает подтверждённый offset; точный повтор чанка допустим,
конфликтующий повтор или дырка отвергаются.
finish проверяет длину, checksum, схему, instance и версии; создаёт staged candidate,
не активируя алгоритмы. Только release(source) делает решение необратимым и выдаёт
activation token; activate(destination) проверяет его хеш и атомарно включает состояние.
Повтор activate не откатывает уже выполненные задачи.

До release: rollback = cancel(destination), затем abort(source). После release
rollback запрещён: восстановление означает повтор activate на том же экземпляре.
При неизвестном результате release нельзя автоматически возобновлять источник.
Только один доверенный control-координатор должен вести перенос. Token подтверждает
решение control-координатора, не является распределённым consensus/lease.

Checksum проверяет целостность, mTLS защищает транспорт. Это не цифровая подпись snapshot
и не шифрование хранимого файла. Дискового файла нет. Tombstones и token metadata живут
только в RAM, до 1024; дальнейшие операции закрываются при заполнении, без тихого удаления.
Resume работает между сетевыми запросами, пока оба процесса/буфер живы.
После рестарта instance меняется и старый перенос не возобновляется. Крах обоих процессов
теряет RAM-состояние. Перенос не заменяет durable recovery или exactly-once для задач.

## Роли и наблюдаемость

client_roles отображает SHA256 DER certificate pin на control/data.
control: attach, legacy snapshot/restore, transfer endpoints.
data: /v1/tasks. Обе роли могут читать status/health/readiness.
Выдача одной роли не включает другую. В localhost dev режиме обе роли разрешены.
Legacy client_pins поддерживается как явно заданный список principals с обеими ролями;
новые конфигурации должны использовать client_roles. Не смешивать оба поля для least privilege.
Горячая ротация allowlist/ключей и revocation в этот этап не входят.

X-Correlation-ID: 1..64 символа из A-Z/a-z/0-9/._-, или UUID сервера.
Ответ возвращает тот же ID. Логи JSON: event, route, status, roles, duration, instance, ID;
без тела записи/snapshot/token. Сетевые ошибки до HTTP (например отказ сертификата)
не имеют correlation ID и полного audit trail пока нет. Health — процесс отвечает;
readiness — running и хотя бы один подключённый алгоритм; 503 иначе.
Перегрузка ограниченных рабочих соединений возвращает 503/Retry-After.
Это не мониторинг CPU/RAM, tracing backend или настройка алертов.

Discovery регулярно проверяет заданные origins, ошибки/timeout не завершают цикл.
Backoff с jitter и пределом, устаревшие cached records не возвращаются;
choose повторно проверяет instance и наличие нужного алгоритма.
Узел может умереть после проверки: адаптер сообщает ошибку и не повторяет задачу автоматически.
Split-brain/реестр с leases, актуализация конфигурации без простоя и task deduplication отложены.
